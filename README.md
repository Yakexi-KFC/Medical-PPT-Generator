# 肿瘤病例 PPT 生成工作台

Streamlit 应用：上传影像、病理、免疫组化、基因检测及检验报告图片，结合病史，生成可编辑的病例汇报 PowerPoint。默认采用 `standard_case`：白底、宋体正文、黑色居中标题和红色横线，不添加医院 Logo。一般以 10—16 页组织病例，正文以完整句子或分点叙述为主，真正需要比较的连续检查才使用表格。

## 使用

1. 在侧栏输入 DeepSeek API key，或通过部署环境配置。会话输入不会写入代码或导出文件。
2. 批量上传图片，可补充病史和治疗经过。点击 **识别检查图片 / 重试失败项**。
3. 展开每张资料，核对检查类型、日期、要点和原文；对照原图与裁剪图，用左右、上下范围调整裁剪，也可精确输入四个边界。多区域图片可逐个调整，也可取消纳入某张图或某个区域。可用“重新识别本图”单独重读；失败时保留上一次结果。图片识别记录可在生成幻灯前独立下载。
4. 点击 **整理病例并生成图文 PPT**。按检查类型、日期及治疗阶段合并相近内容：病例概况、病理结论、治疗经过和总结使用完整句子或分点；多次影像、检验可用纵向对照表。病理、影像页保留完整报告主体、完整显微图组或影像面板，避免把报告拆成大量文字小截图。有可追溯日期的诊疗节点时，自动加入可编辑时间轴，已执行治疗与后续建议分别标记。明确记录的一线、二线等系统治疗分别展示；原文未写明线数时仅写治疗阶段或方案，不因顺序自动编号。同药减量、维持治疗及 TAE 等局部治疗不单独增加系统治疗线数。
5. 下载 PPT 和 **识别与配图记录**。已有明确的 `presentation_plan` 时，页面显示核对后的计划页数，按计划放置报告或图组，不显示旧的 **幻灯放置位置** 控件。未指定逐页计划时仍可调整检查所属章节。修改裁剪或有效的位置设置会自动更新下载文件；修改病史、检查文字或纳入资料后，需要重新整理病例或导入更新后的完整核对记录。

不上传图片时，可以直接粘贴病历生成。图片中的病例文字、检查结果和裁剪区域均由 DeepSeek API 识别。

### 恢复已核对的病例

按原顺序上传同一批图片并填写相应病史，在 **导入已核对的识别记录** 中选择 JSON，点击 **应用核对记录**：

- 仅含 `analyses` 的图片识别记录恢复检查文字和裁剪。
- 同时含 `case` 与 `analyses` 的完整配图记录恢复病例结构、文字、表格、时间轴和 `presentation_plan`。页数取决于已保存的计划，不强制所有病例具有相同页数。
- 完整病例记录须覆盖本批全部图片。导入会检查来源编号、裁剪区域、页结构和治疗阶段引用，拒绝其他批次图片或不存在的裁区；所有内容通过校验后才替换当前结果。

默认 `presentation_mode` 为 `compact`；确需详细分段版时可在病例 JSON 中设为 `detailed`。存在 `presentation_plan` 时优先按其逐页结构生成，不自动追加全部报告截图。修改逐页结构后可将完整记录重新导入。

`presentation_theme` 默认 `standard_case`；设为 `legacy` 可沿用此前的深红色标题栏主题，`default` 保留为该旧主题的兼容别名。主题与 `compact` / `detailed` 的内容组织方式可以分别选择。

逐页计划支持下列图文设置：

- `images[].display_mode` 省略或为 `region`：使用该图已核对的 `region_id`；省略区域编号时取第一条有效裁区。完整报告主体或完整图组可以作为一个裁区保留。
- `images[].display_mode="full"`：明确插入整张原图，不能同时指定 `region_id`。该方式不执行裁剪，因此原图中已有的内容都会保留；需要去掉界面边框或身份区域时应选对应的报告主体裁区。
- `layout="image_left"` 或 `"image_right"`：图片使用约 6.6 英寸宽的一栏，文字使用约 5 英寸宽的另一栏，可在同页并列完整报告和图组。`bottom` 则在正文下方放图；省略时自动安排。
- `layout="report_pair"`：恰好选择两张图，第一张在左侧显示完整报告，第二张在右上显示放大的完整图组，右下保留 18 pt 可编辑摘要。一个正文段落约 100—130 汉字、最多约六行较合适；超出部分自动续页，不截断事实。该版式用于正文页，不用于封面。

所有模式都校验本批来源编号。错误裁区不会转成完整原图，完整原图模式也不能引用其他病例的资料。

### 时间轴

标准时间轴使用双列纵向布局，每列最多 5 个节点，每页最多 10 个；长正文或更多节点会完整续页。节点日期、阶段及正文均为原生可编辑文本。治疗使用实心标记，`Treatment Plan` / `Plan` 使用灰色空心标记并显示为后续建议。

逐页计划中的时间轴页使用 `type="timeline"`，`events` 为节点数组，每项包含 `date`、`phase`、`event_type`、`event`。支持的事件类型为 `Surgery`、`Biopsy`、`Pathology`、`Genetic Test`、`Imaging`、`Laboratory`、`Treatment`、`Radiotherapy`、`Evaluation`、`Treatment Plan`；`Plan` 会规范为 `Treatment Plan`。可附 `source_asset_id`、`source_quote`、`source_date` 和 `date_basis` 保留来源。省略 `events` 时使用本病例已核对日期的 `timeline_events`；时间轴页不能混放图片、表格或普通正文段落。跨多个治疗阶段时，可设 `section="treatment"` 并省略 `treatment_index`。

时间轴应概括手术、方案开始或调整、放疗、关键疗效评估及后续计划，重复给药可按来源日期和方案集中呈现。日期允许保留原文月份及范围；不将入院日或 CT 日期自动赋给随后未注明日期的操作，也不把只有月份的记录补成具体日。原文没有明确线数时，节点只显示阶段或方案。

新生成的 API 结果若给出逐页计划但漏掉时间轴，且存在可追溯的日期节点，程序会在首个治疗页前补入时间轴；原计划已达 30 页时会明确报错，不删除已有页面。手工导入已核对的逐页计划时，保留用户的页面顺序，不自动增加时间轴页。

## 本地运行

```powershell
python -m pip install -r requirements.txt
python run_local.py
```

当前电脑已安装工作区依赖时，也可运行 `./start.ps1`，打开终端显示的本地网址。使用 `Ctrl+C` 停止服务。

## 部署配置

入口文件为 `app.py`。部署时同时包含本目录生产 `.py` 文件、`requirements.txt` 和 `.streamlit/config.toml`，以保持应用逻辑、依赖及上传上限一致。

通过环境变量或 Streamlit Secrets 配置：

```toml
DEEPSEEK_API_KEY = "your-key"
```

`.streamlit/secrets.toml` 已加入 Git 忽略列表。不要提交真实密钥。

## 图片与幻灯流程

- 图片识别使用 `deepseek-flash`，`image_url` base64 输入和 `detail="original"`；病例整理可选择 `deepseek-v4-pro` 或 `deepseek-flash`。
- 一张原图对应一次识别请求。默认再对完整报告精读一次：以全图概览对齐行列，原始像素分块保留重叠。精读独立读取整张图片，裁剪范围只决定配图，不会限制文字识别覆盖范围。可在侧栏关闭。单图失败保留其他图片结果，重试只处理失败项。
- 网页接受 PNG、JPEG、WebP；每张最大 40 MiB、2000 万像素，每批最多 30 张、240 MiB、1.2 亿像素。`.streamlit/config.toml` 的单文件上传上限为 40 MB。超限或损坏图片需要从上传列表移除或替换。
- 先校正 EXIF 方向，再统一以 0—1000 整数坐标定位。裁剪使用原分辨率像素，输出 PNG；幻灯中的图像保持比例，图片说明、日期及病例文字可编辑。
- 紧凑模式集中整理检查要点，优先保留完整报告主体、显微图组及影像面板。默认病理和单次检查用叙述，多个日期的影像或检验可使用对照表；没有提供 CT/MRI 原始图像时不会合成或替用其他病例图像。
- 单个计划页最多并排放三张图，超出部分续页。文字或表格超出可读空间时自动续页，配图记录可追溯至来源编号、裁区、完整原图/裁图显示方式和幻灯页码。
- 检查日期用于校准治疗阶段。严格匹配的同报告原图与放大图归为一组，保留各来源与配图记录；不凭相似诊断合并独立检查。
- 图片和病例保留在当前 Streamlit 会话内，刷新/关闭会话后可能丢失。识别操作会把纳入的图片提交到 DeepSeek；识别文字不抄录直接身份字段，裁剪结果仍可对照原图检查。
- AI 输出经过 JSON、图片 ID、区域 ID 和坐标校验；不根据检查图片自行补写诊断、分期、疗效、治疗线数或生存期。

官方接口依据（2026-10-18 核对）：[图像理解](https://api-docs.deepseek.com/guides/vision/) · [JSON 输出](https://api-docs.deepseek.com/guides/json_mode/)

## 验证

```powershell
python -m unittest discover -s tests -v
```

测试包含 API 格式模拟、EXIF 方向、实际像素裁剪、大文件上传归一化、异常 JSON、阶段映射、紧凑页计划与来源校验、完整原图的明确选择、左右图文布局、标准病例主题、时间轴日期和计划区分、API 漏页补入、可编辑表格及分页、完整病例恢复，以及 Streamlit 状态保持。测试不调用真实 API。真实识别质量须在配置 key 后用实际检查资料测试。

实际大图的本地像素验收可使用 `tests/acceptance_large_images.py`：传入图片目录、指定文件名和 JSON 输出路径，逐张调用生产 `prepare_asset`，核对 EXIF 校正后的尺寸、全部像素哈希及整图裁剪结果；验收不调用 API，也不复制原图到结果文件。
